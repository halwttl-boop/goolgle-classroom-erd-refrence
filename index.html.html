Google Classroom ERD Architecture Reference

1. Functional Layers (14 Tables)

Functional LayerIncluded TablesResponsibility
Layer 1: Identity & EnrollmentUSER_PROFILES, COURSES, COURSE_ROSTERS, INVITATIONS, GUARDIANSManages user identities, class definitions, course-specific roles, pending email invites, and parent links.
Layer 2: Stream & OrganizationTOPICS, ANNOUNCEMENTS, COURSEWORKSeparates ungraded class announcements from graded assignments and organizes work into unit folders.
Layer 3: Grading & SubmissionsSTUDENT_SUBMISSIONS, SUBMISSION_HISTORY, RUBRICS, RUBRIC_CRITERIATracks student turn-ins, draft vs. returned scores, structured grading rubrics, and audit logs.
Layer 4: Media & DiscussionATTACHMENTS, COMMENTSStores Drive files, YouTube videos, web links, and public or private comments across all items.

2. Core Architectural Design Decisions

Design ChoiceArchitectural Rationale
Roles in COURSE_ROSTERSStores TEACHER or STUDENT per course rather than on USER_PROFILES, allowing one account to teach one class while taking another.
INVITATIONS → COURSE_ROSTERSPending email invites stay in INVITATIONS (PENDING) until accepted, then transition into a permanent COURSE_ROSTERS row.
Dual FKs on STUDENT_SUBMISSIONSStoring both coursework_id and course_id allows the teacher's Grades tab grid to load an entire class gradebook in one fast index query.
draft_grade vs. assigned_gradeTeachers stage private scores in draft_grade; clicking Return copies the score to assigned_grade and updates state to RETURNED.
SUBMISSION_HISTORY Audit LogAppend-only timeline logging every turn-in, unsubmit (RECLAIMED_BY_STUDENT), and grade update with timestamps and actor_id.
3 Nullable FKs on Media/CommentsEach row in ATTACHMENTS or COMMENTS fills exactly one of ann_id, coursework_id, or submission_id, avoiding 6 duplicate tables while maintaining real SQL foreign keys.

4. End-to-End Data Lifecycle

StageDatabase Activity
1. SetupTeacher creates a row in COURSES (C101). Twenty students join via enrollment_code, creating 20 rows in COURSE_ROSTERS with role_type = 'STUDENT'.
2. PublishingTeacher creates a TOPICS unit ("Unit 1") and posts an essay in COURSEWORK (max_points = 100), attaching a PDF in ATTACHMENTS and a grading grid in RUBRICS + RUBRIC_CRITERIA.
3. Auto-InitUpon publishing, the system automatically inserts 20 blank rows into STUDENT_SUBMISSIONS (one per student) with state = 'CREATED'.
4. SubmissionStudent attaches their Google Doc in ATTACHMENTS and clicks Turn In. STUDENT_SUBMISSIONS updates to TURNED_IN (setting late_flag if overdue), and SUBMISSION_HISTORY logs the timestamp.
5. GradingTeacher leaves a private note in COMMENTS (is_private = TRUE), sets draft_grade = 92, and clicks Return. assigned_grade becomes 92, state becomes RETURNED, and SUBMISSION_HISTORY logs the release.

5. Delete Cascade Rules

Delete RuleEffect on Related Tables
ON DELETE CASCADEDeleting a COURSE automatically removes its rosters, topics, announcements, coursework, and submissions. Deleting a RUBRIC removes its RUBRIC_CRITERIA.
ON DELETE SET NULLDeleting a TOPIC sets topic_id = NULL on COURSEWORK, safely moving assignments to the top of Classwork without losing student grades.
RESTRICT / No CascadeDeleting a USER_PROFILE is blocked if they own active courses or appear in historical grade audit logs.
